# 01  项目架构概述

项目采用“单渲染器 + 多内容模块 + 单物理世界”的微缩城市架构。Three.js 负责渲染与相机，Rapier 只负责需要真实碰撞的玩法（驾驶、投掷等），Vite 负责开发与生产构建。

## 1.1  技术栈与版本

| 层 | 技术 / 版本 | 在本项目中的职责 |
| --- | --- | --- |
| 渲染 | Three.js 0.187 | Scene / Camera / Renderer / EffectComposer / LOD / InstancedMesh |
| 物理 | Rapier 0.21（@dimforge/rapier3d-compat） | 唯一 world.step；玩家车、投掷物、临时 collider |
| 构建 | Vite 8.3 | 开发服务器、生产构建、vendor 分包 |
| 语言 | JavaScript（ES Modules） | 无 TypeScript；靠契约、测试与注释约束 |
| 测试 | Node + Playwright + Edge Headless | 验收脚本直接读 window.__playground 运行时状态 |
| 文档 | docx 9.15.4 | 本交接文档生成（只用于脚本，不进运行时） |

## 1.2  启动与渲染链路

| index.html<br>  └─ src/main.js<br>      ├─ SceneManager        唯一 renderer / camera / composer / 渲染循环<br>      ├─ AttractionManager   注册、激活、卸载、dispose 调度<br>      ├─ PhysicsManager      Rapier 懒加载；全工程唯一 world.step<br>      ├─ CameraRig           相机 owner 仲裁；设施/步行/驾驶互斥<br>      └─ Lobby               常驻世界根节点<br>          ├─ Zoo / Castle / Farm / ForestPark<br>          ├─ Districts       四宫格骨架 + 区域级 LOD<br>          └─ Metropolis      北侧 CBD / 交通 / 人群 / 驾驶<br> <br>每帧逻辑顺序（简化）：<br>  physicsManager.step(dt)  →  attractionManager.update(dt)<br>  →  cameraRig.update(dt)  →  composer.render() |
| --- |

关键点：大厅本身不是“一个设施”，而是常驻世界；动物园、城堡、农家乐、森林公园、都会区都挂在大厅根节点下。进入小游戏只是激活一个设施副本，世界不被销毁。

## 1.4  五个必须保留的架构决策

零外部资产：所有外观由程序化几何 + Canvas/DataTexture 生成；不依赖 glb、贴图或音频文件。

单渲染器 / 单物理世界：不要新建 WebGLRenderer，不要另起 Rapier world。

按需物理：Rapier 只在真正需要物理的设施或驾驶时动态 import；启动不预取。

资源台账：几何、材质、纹理、InstancedMesh 必须成对 dispose；大厅有七步清理流程。

脚本守门：性能与功能验收都落成 tests/*.mjs，不靠肉眼判断“应该没问题”。

| 架构层面的“不要创新”<br>这里不是从零搭框架的舞台。新增模块应复用 SceneManager、AttractionManager、PhysicsManager、CameraRig 与资源台账；另起一套生命周期，通常会以相机双写、资源泄漏或物理世界冲突收场。 |

## 2.3  坐标命名的坑

| “南门”是建筑名，不是 +z 方向<br>代码口径中 +z 指向四宫格北侧与都会区，南门只是入口建筑的命名。不要根据“南门”推断坐标正负，也不要据“北侧都会区”反推相机朝向。<br>新增内容时，以 DISTRICT_GRID、CITY、ZOO_LAYOUT、FOREST_PARK 为单一真相源；手写坐标前先 grep 这些常量。 |
| --- |

道路红线：主干道 x=24、净宽 16m（13m 车行道 + 两侧 1.5m 人行道）；所有建筑体量离道路红线至少 2m。城市扩展先跑 isOnRoad() 扫描，不要靠目测。

四宫格边界：outer 为 x∈[-30,90]、z∈[-30,90]；北侧两区通过 z=27 的横路连接。城堡与农场的几何是世界坐标烘焙进顶点的，移动区域时要同步 _rebase，不能只改 group.position。

# 03  全局系统实现

全局系统共享一条原则：热路径只改标量、矩阵、uniform 或 DOM 文本，不在 update 里创建 GPU 资源。下面的实现细节，是接手时最值得先读的部分。

## 3.1  昼夜循环

入口：src/utils/helpers/day-night-cycle.js；由 Lobby 右下时间台和自动循环驱动。

| 模式 | 视觉基调 | 关键参数（标定后） |
| --- | --- | --- |
| 白天 day | 日光、清晰远景、轻 Bloom | 主光 0.58；环境 0.07；曝光 1.0；Bloom 0.06 / 阈值 1.4 |
| 黄昏 sunset | 橙色天空、长阴影、霓虹初亮 | 主光约 0.31；曝光 0.94；Bloom 0.22 / 阈值 0.95；霓虹 ×1.7 |
| 黑夜 night | 深蓝夜空、月亮/星空、霓虹与窗光 | 主光约 0.04；曝光 0.86；Bloom 0.55 / 阈值 0.55；霓虹 ×3.6 |

自动循环：默认关闭；开启后 480s 一轮（可设 300–600s），在 day → sunset → night 之间插值。

统一驱动：太阳/月亮、星空、天空球、雾、环境光、霓虹 emissive、Bloom 强度都在同一状态机里过渡。

四季联动：season-cycle 通过 setSeasonLightScale() 调整主光，不另起一套灯光。

设施上下文：嵌入设施通过 registerEmbeddedContext() 注册，不复制昼夜逻辑。

## 3.2  四季天气与粒子池

入口：src/utils/helpers/season-cycle.js + src/utils/helpers/particle-system.js。

| 季节 | 植被基调 | 天气 | 发射量 / 节奏 |
| --- | --- | --- | --- |
| 春 spring | 嫩绿地面、亮绿阔叶、深绿针叶 | 花瓣 petal | 每次 16 枚，间隔 0.26s |
| 夏 summer | 深绿、浓密、太阳最强 | 阵雨 rain + 地面波纹 | 每次 36 滴，间隔 0.13s；间歇阵雨 |
| 秋 autumn | 黄褐地面、橙红阔叶、针叶保持深绿 | 落叶 leaf | 每次 16 片，间隔 0.24s |
| 冬 winter | 雪白地面、冷色树冠 | 雪花 snow | 每次 24 片，间隔 0.18s |

材质分角色注入：ground / broad / conifer / shrub / grass 五个角色分别持有 uniform，切换时只 lerp 颜色。

天气复用烟花系统的 3000 粒子池与同一套 Points 几何；weather 只是第二个绘制批次，不新建几何/纹理。

峰值上限：weather 同时最多 760 个粒子；clearWeather() 后槽位全部归还（freeTop=3000）。

update 中绝不 new 粒子：只从池中取、写属性、归还；8 次四季切换实测 Δgeo=0 / Δtex=0。

## 3.3  红绿灯交通流

入口：src/scenes/metropolis/city-signals.js + city-traffic.js + city-street.js。

| 对象 | 数量 / 实现 | 性能策略 |
| --- | --- | --- |
| 行驶车 | 10 辆，3 条闭合路线 | 车身/车顶/车轮各一个 InstancedMesh；路线 256 点预采样 |
| 停放车 | 2 辆，位于 (-30,98) 一带 | 同一 InstancedMesh 的实例；可被玩家认领 |
| 公交 | 1 辆，沿公交路线循环 | 独立低模 Mesh；到站触发下客 |
| 信号灯 | 9 个十字路口，灯头实例化 | 按轴相位；车辆在停车线前减速 |
| 路灯 / 地面光斑 | 街道设施，InstancedMesh | 夜间切换透明度，不新增灯源 |

路线：CatmullRom 预采样 256 点；运行时只推进标量 t/s，再按车道法线偏移 ±3.25m，不在每帧重算样条。

信号：车辆按前方最近路口和轴向读灯色；红灯/黄灯在停车线前停，绿灯恢复目标速度。

公交：BUS_STOP (32.4,38)；到站触发 CityCrowd.activateAlighters()，下客后继续行驶。

夜间：头灯/尾灯/地面光斑由 setNight() 统一调透明度；不新增 PointLight。

## 3.4  GTA 驾驶

入口：src/scenes/metropolis/city-driving.js；Lobby 负责 F 键仲裁与 HUD。

| 项目 | 实现值 / 行为 |
| --- | --- |
| 上车条件 | 玩家在 WASD 或地面漫游模式、距最近 AI 车 ≤4.2m；HUD 显示「按 E 上车」。飞行模式高空不触发 |
| 玩家车 | Rapier dynamic body；6 个视觉部件复用 CityTraffic 的 body/cabin/wheel 几何 |
| 质量 / 碰撞 | 约 321.5 kg；一个 cuboid collider；X/Z 旋转锁死，只保留 Y 轴转向 |
| 动力 | W/S：前进 9.5 m/s²；制动 -13.5；倒车 -5.2；前进上限 17.5 m/s（约 63 km/h） |
| 转向 | A/D：目标角速度 1.45 rad/s；低速转向弱，倒车自动反向 |
| 横向抓地 | exp(-8.5·dt) 衰减；地面摩擦 0.05，避免蹭地拖慢 |
| AI 车辆 | 最多 12 个 kinematic 包围盒（10 行驶 + 2 停放 + 1 公交，扣除当前认领车）；不升级为动态物理 |
| 物理体数量 | 驾驶中 14 个（1 静态 + 1 玩家 + 12 AI）；下车后 0 个 |
| 下车 | E 退出；车身左侧 2.1m 找落点；AI 车留在停车位置；相机交还 WASD / 地面漫游（漫游层自动恢复） |

| 驾驶系统的性能边界<br>玩家车保留完整物理；AI 车只做简化运动学包围盒。不要为了“更真实”把 12 辆 AI 车全部改成动态刚体——那会同时击穿物理 CPU 预算与稳定性。<br>玩家车视觉不新建几何：6 个部件全部复用交通系统的 body/cabin/wheel；材质只在首次上车创建一次。 |
| --- |

## 3.5  NPC 状态机

入口：src/utils/helpers/npc-manager.js（大厅 10 个 NPC）；src/scenes/metropolis/city-crowd.js（都会区 11 个低模行人）。

| 维度 | 大厅 NPC | 都会区行人 |
| --- | --- | --- |
| 数量 | 10 个（4 个入口迎宾 + 6 个巡游） | 11 个（6 walker + 2 医院访客 + 3 公交下客） |
| 渲染 | 1 个 InstancedMesh = 1 draw call | 身体/头/腿各一个 InstancedMesh |
| 状态 | WALK / IDLE / LOOK / WAVE 四态 | 沿路径行走 / 到站下客 / 访客路径 |
| 寻路 | BFS 导航图，2.4m 网格、八邻域；AABB 避障 | 预采样路径 + 碰撞回退 |
| 动画 | 顶点着色器驱动走路/摆臂/挥手/张望；CPU 只写 aAnim | 实例矩阵 + 简单摆动 |

状态迁移是手写字段 + dt 累计，不是通用 FSM 框架；新增状态时沿用现有状态表，不要另建第二套计时器。

BFS 路径的相邻点必须通过 AABB 线段检测；斜穿墙角是历史 bug，已通过整段采样修复。

NPC 边界与玩家边界不同：大厅 NPC 默认 NAV_RADIUS=31，M7 后可通过 setBounds 扩展；不要误用玩家 110m 边界。

| 设施 | DetailLOD 包装 | 90m / 115m 阈值；设施内部再按需简化 |
| 重复物件 | InstancedMesh | 树、作物、车辆、动物、行人、路灯、金币、灯泡 |
| 后处理 | RenderPass → Bloom → FXAA → OutputPass | ACES Filmic；移动端关 Bloom、降阴影/折射 |
| 阴影 | 单一方向光投影 + 2048²（按画质降档） | 不新增投影灯；设施级仅跳舞厅等少数例外 |

LOD 必须保持 autoUpdate，让 renderer 在投影阶段自动切换；不要重新“钉死高模”。

新区内容保持 frustumCulled=true；不要为了“永不消失”强制常驻。

北侧城堡/农场几何是世界坐标烘焙的；移动区域时用 _rebase，而不是只改 group.position。

## 4.3  性能红线清单

三角面总量不得超过 300,000；新增内容先估算面数，再动手。

新增内容/新视图 draw calls 不得超过 900；大厅全量 1,198 是既有基数，不要混为一谈。

热路径（update / render）不得 new BufferGeometry、Material、Texture、数组或 Date。

所有重复物件必须 InstancedMesh；不要为 1000 棵树创建 1000 个 Mesh。

所有资源必须进台账并成对 dispose；InstancedMesh 要单独 dispose instanceMatrix / instanceColor。

不得新增常驻灯源或投影灯；夜景优先用 emissive、光斑贴图、Bloom。

不得把 AI 车全部升级为动态刚体；玩家车完整物理，AI 车 kinematic。

不得绕过粒子池上限；四季天气峰值 760，clear 必须归还全部槽位。

不得改 CameraRig 的 owner 仲裁；相机只能有一个写者。

不得为了让测试通过而改红线或基线；基线更新必须单独评审并归档旧值。

### 6.2  工程底座六项加固

相机写者契约统一。CameraRig 成为所有生产相机写入的唯一通道：一次性机位切换走 blendTo/restore（带过渡），逐帧跟随走新增的 writePose（受控直写、零分配）。直写者必须先 allowDirectWrite(key) 登记，无 owner / 未登记一律拒绝并告警；写入计入 directWriteCount 审计。原先绕过 rig 的两处——CityDriving._syncVisual 与 Lobby._updateZooFly——已改走 rig。验收脚本：tests/verify-camera-contract.mjs（7/7）。

全局系统上下文收敛。main.js syncGlobalContext() 统一同步 dayNight / firework / npc / season 四个单例；此前四季只靠 Lobby 生命周期隐式管理，独立设施卸载后天气不会挂起。

粒子池按类型隔离回收。天气（kind≥4）与烟花/文字（kind=0）互不误杀；天气配色表提为模块级常量，发射热路径零 JS 分配。

漫游与驾驶集成修复（本次实操 bug）。六项升级的 movementMode（按 F 漫游）与驾驶曾互斥：玩家用漫游走到车旁后，因 movementMode.isEngaged()=true 使车辆扫描条件恒假，靠近车按 E 完全无反应。修复为：地面漫游允许扫车、飞行模式不扫；驾驶期间漫游层自动让位（保留 engaged 标志、下车自动恢复），避免与驾驶相机双写。验收脚本：tests/verify-drive-roam.mjs（7/7）。

联合回归门禁。新增 tests/verify-all.mjs，串行跑 build + camera + redline + v4 + season + driving + drive-roam + phase2 + m6zoo，任一失败整体非零退出，支持 --only 缩跑。45 个一次性探针归档至 tests/_archive/。

### 6.3  驾驶操作说明（重要）

上车：先靠近车辆（地面漫游 / WASD 第一人称均可，距≤4.2m；轨道模式把视线中心对准车、距≤6m），出现「按 E 上车」提示后按 E，或点击该提示直接上车。首次上车会懒加载 Rapier 物理世界，短暂显示「正在上车」。

驾驶：W/S 加减速、A/D 转向、C 在驾驶位 / 第三人称间切换、E 或点击提示下车。上车点位于都会区停车场 (-30, 98) 一带，沿 x=24 主干道从 z=90 向 +z 步行可达。

漫游兼容：按 F 进入 / 退出漫游；地面模式可靠近并上车，飞行模式在高空不会触发上车提示。上车时漫游层自动让出相机，下车后自动恢复，无需重新按 F。

自救：卡住时按 R 回到大厅出生点。
