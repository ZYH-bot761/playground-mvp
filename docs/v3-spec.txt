游乐园项目 v3 完整提示词（九大模块）

执行总则：本提示词包含 9 个模块，必须按 模块0 → 模块9 → 模块1 → 模块2 → 模块3+4 → 模块5 → 模块6 → 模块7 → 模块8 的顺序逐个完成，每完成一个模块必须自检通过（见各模块「验收标准」）后再进入下一个，禁止跳过、禁止并行猜测、禁止在后续模块中破坏前置模块的成果。
落地前第一步（强制）：先完整阅读 Lobby.js、IAtraction（或同等接口定义）、Carousel.js、PirateShip.js、旧的金币小路文件、旧的跳跳球文件、main.js/入口文件，在报告开头列出：① 设施基类接口签名（init/update/dispose/enter/exit 参数与返回值）；② 相机接管与归还方式；③ 大厅现有场景结构（地面、装饰物、椅子、旋转木马摆放位置与命名）；④ 现有昼夜/光照代码位置。读完再动手，不要凭假设写代码。

模块 0：全局强制约束（所有模块共同遵守）

0.1 帧率无关性：所有运动、动画、计时基于 clock.getDelta() 累加，dt 上限截断为 0.1s，防止切后台回来瞬移。禁止依赖帧数、禁止固定步长。

0.2 资源生命周期：几何体、材质、贴图在 init 中创建，在 dispose 中释放。禁止在 update/render 循环内 new 任何 Three.js 对象（Vector3、Quaternion、Color、Matrix4 等一律在 init 预创建并复用）。

0.3 DOM 管理：所有 UI 浮层绝对定位 + pointer-events 控制；退出设施时必须 remove() 并解绑事件监听，或 display:none + 置空引用。禁止残留游离 DOM。

0.4 相机归属：游玩期间相机由设施接管，退出时必须完整归还给大厅 OrbitControls（恢复 position/target/enabled/fov）。禁止把 camera add 进任何设施 Group，跟随一律用「读取世界坐标 → copy」方式。

0.5 纹理色彩空间：所有 CanvasTexture 必须设置 texture.colorSpace = THREE.SRGBColorSpace（r152+）。未设置会导致颜色发灰/过曝——这是「看起来很假、很 AI」的头号元凶之一。

0.6 性能预算（强制硬指标）
检索证据  给出行业治理基准：Draw Call < 50、三角面 < 300,000、场景切换必须递归执行 geometry.dispose() / texture.dispose()。
检索证据  给出具体手段：renderer.setPixelRatio(Math.min(window.devicePixelRatio, 1.5))（上限 1.25~1.5 已足够清晰）；同材质静态网格合并；重复对象用 InstancedMesh；用 renderer.info.render.calls 排查 draw call 来源。
本项目验收线：大厅静态场景 renderer.info.render.calls ≤ 120；任意单个设施游玩中 ≤ 200；全场景三角面 ≤ 300,000；中端笔记本稳定 ≥ 55fps。
每个模块交付时必须附上 renderer.info.render.calls、renderer.info.render.triangles、renderer.info.memory.geometries/textures 的实测数值。

0.7 泄漏验收：init → play → dispose 完整周期后，renderer.info.memory.geometries 与 .textures 必须回落到 init 前水平。每个模块都要跑一遍并报告数值。

0.8 反「AI 感」总原则（模块 9 展开，此处先立规矩）
禁止纯色塑料质感、禁止所有物体共用同一个 roughness/metalness、禁止均匀无衰减的平光、禁止物体像贴纸一样浮在地面上（必须有接触阴影或 AO 暗示）、禁止比例失真（人、椅子、门、设施之间必须有真实尺度关系）。

模块 1：跑酷 ParkourRun.js（替换旧「金币小路」）

1.1 定位
删除旧的金币小路文件，新建 ParkourRun.js。风格与玩法对标《地铁跑酷》(Subway Surfers)：三轨道无尽跑酷 + 躲避障碍 + 沿途收集金币。

检索依据（）：《地铁跑酷》核心为「在三条铁轨上左右滑动、跳跃、滑行，躲避迎面驶来的列车和障碍物，一边吃金币一边被追赶，跑得越远分数越高」；操作为「向上滑跳跃（躲低矮障碍）、向下滑翻滚/滑铲（躲高空障碍）、左右滑切换轨道」；失败机制为撞到火车/障碍物；道具含磁铁吸金币、飞行背包、双倍得分、超级跑鞋（跳更高）、滑板（抵消一次失误）；且「跑着跑着速度会自己往上提」。

1.2 视觉构建
三轨道地面：3 条平行跑道，每条宽 1.6~2.0 单位，跑道间距 0.2~0.3 单位（缝隙），总宽约 6 单位。用长条 BoxGeometry 做地面，贴 CanvasTexture 生成的柏油/砖石纹理（重复 UV），roughness 0.75~0.9。
两侧环境：低多边形建筑（BoxGeometry 拼搭，带窗户贴图）、路灯（CylinderGeometry + SphereGeometry + PointLight）、围栏。两侧环境必须向后无限滚动复用，不得无限生成新对象。
障碍物类型（至少 4 种）：
  低矮箱/路障 → 需跳跃
  高空横杆/低矮通道 → 需滑铲
  整条轨道被长条形「列车车厢」占满（需换轨，或跳上车顶继续跑）
  静态墙体（占 1~2 条轨道，不可跨越，只能换轨）
金币：OctahedronGeometry 或 CylinderGeometry（扁圆片状，边缘倒角感），metalness 1、roughness 0.05、emissive 0x553300（微弱自发光避免暗处全黑），沿轨道呈直线/弧形/波浪形排布。
主角：CapsuleGeometry（身体）+ SphereGeometry（头）+ BoxGeometry（四肢）拼搭的低多边形小人，带简单跑步摆臂摆腿动画（用 sin 驱动 rotation，不引入骨骼）。

1.3 无尽滚动机制（关键实现）
不要让角色真的跑出无限远，而是：
角色固定在 z = 0 附近（仅做轨道横移与跳跃的局部位移）。
所有障碍物、金币、环境物体向 +z 方向移动（即朝相机方向），速度 = currentSpeed。
物体移出相机后方（z > despawnZ）后，回收到对象池，重置到前方 spawnZ 处并重新生成内容。
使用 THREE.InstancedMesh 承载金币与环境重复件（检索依据：同材质重复对象优先 InstancedMesh，可把数千 Mesh 压到 1 次 draw call）。障碍物若类型不同则各自一个 InstancedMesh，或用少量对象池 + 普通 Mesh（总数控制在 60 个以内）。

1.4 操控
输入   动作
← / → 或 A/D 或 左右滑动   切换轨道（平滑插值 0.12~0.18 秒到位）

↑ / W / 空格 或 上滑   跳跃（抛物线，滞空 0.55~0.75 秒）

↓ / S 或 下滑   滑铲（持续 0.5 秒，碰撞盒高度降低，期间不可跳）

空中允许变轨（检索依据  明确提到「主角在空中的时候也可以左右控制方向」）。
输入必须有缓冲：起跳前 0.1 秒内的输入也应生效，避免「按了没反应」。
移动端同时支持触摸滑动（判定阈值：位移 > 30px 且主方向明确）。

1.5 速度与难度曲线
起始速度 12~15 单位/秒，每 10 秒 +0.6~0.9，上限 28~32。
障碍密度随速度提升（检索依据：「节奏由障碍密度和速度决定」）。
必须保证任何时刻至少有一条轨道可通过，禁止生成三轨道全堵死的死局。生成器每次只在 3 条轨道中最多封堵 2 条。

1.6 碰撞与判定
用 AABB 包围盒粗筛（同轨道 + z 区间重叠），不用 Raycaster 逐帧检测（性能考虑）。
角色碰撞盒：站立时 宽0.8 × 高1.7 × 深0.8，滑铲时高度降为 0.7。
撞上障碍 → 触发失败（可给 1 次「复活/护盾」机会，见 1.7），第二次直接结算。
金币拾取：z 区间重叠 + 同轨道 + y 差 < 1.2 → 自动吸附，播放缩放消失动画，coins++。

1.7 道具（至少 3 种）
依据  列出的真实道具：
磁铁：持续 8 秒，自动吸附半径 6 单位内所有轨道的金币（金币向角色位置插值飞行）。
双倍得分：持续 10 秒，金币与距离得分 ×2。
飞行背包 / 喷气背包：持续 5 秒，角色升至高空（y ≈ 6），期间不撞地面障碍，可收集空中金币层。
4.（可选）护盾/滑板：抵消一次碰撞。

道具以悬浮旋转的礼盒（BoxGeometry + 自发光边缘）出现，触碰即激活，HUD 显示剩余时间条。

1.8 UI 与流程
进入 → 显示「开始跑酷」按钮 + 操作说明浮层（键盘/滑动图示）。
点击开始 → 3-2-1 倒计时 → 开始奔跑。
HUD：左上角当前得分（距离 + 金币）、右上角金币数、道具栏（含倒计时环）。
失败 → 0.5 秒慢动作 + 相机轻微后拉 → 结算浮层：本次得分、金币数、最远距离、历史最高（localStorage）、再来一次、返回大厅。
退出必须归还相机 + dispose 全部资源。

1.9 相机
第三人称跟随：位于角色后上方 (0, 3.2, 6.5) 相对偏移，lookAt 角色前方 (0, 1.2, -4)。相机随轨道横移做 0.08~0.12 秒的延迟跟随（lag follow），产生速度感。禁止任何随机抖动（检索依据：晃动过快是 3D 眩晕主因）。可选：速度提升时 FOV 从 65° 平滑增至 75°，增强冲刺感。

1.10 验收标准
三轨道切换手感跟手，无穿模、无卡轨。
连续跑 5 分钟不掉帧（实测 FPS 曲线）、draw call 稳定不增长。
无死局（用自动化脚本或手动跑 3 局验证）。
对象池工作正常：geometries 数量在整局中保持恒定。

模块 2：跳一跳 JumpJump.js（替换旧「跳跳球」）

2.1 定位
删除旧跳跳球，新建 JumpJump.js，严格复刻微信《跳一跳》的核心机制。

检索依据（）：玩家扮演黑色小人，在方块跳板间跳跃；长按屏幕蓄力，按住时间越长跳得越远，松手后沿抛物线飞出；落空则游戏结束；跳到方块 +1 分，跳到方块中心 +2 分，连续跳中心得分递增 2→4→6→8…最高连续 16 次达 32 分，此后每次均为 32 分；偏离中心或落普通位置则连击中断；特殊方块停留触发彩蛋加分：音乐盒 +30、便利店 +15、魔方 +10、井盖 +5；随分数上升落地区域逐渐变小。

2.2 视觉构建
跳板方块：BoxGeometry（正方体/长方体）为主，穿插 CylinderGeometry（圆柱/井盖）、ConeGeometry（尖顶，不可停留）。尺寸随分数递减：初始边长 1.6~2.0，每 500 分递减 5%，下限 0.6。
小人：CapsuleGeometry（黑/深灰身体）+ SphereGeometry（头），roughness 0.6、metalness 0.1。蓄力时身体压扁（scale.y 从 1.0 → 0.75，scale.xz 反向膨胀 1.0 → 1.2），模拟  描述的「小人会下蹲蓄力」。
方块材质差异化（反 AI 感关键）：普通方块为哑光漆面（roughness 0.7）；魔方为高光塑料（roughness 0.25）；井盖为铸铁（metalness 0.9、roughness 0.35，贴 CanvasTexture 生成的锈斑）；便利店为带窗户与招牌的小房子。
背景：柔和渐变天空（CanvasTexture 球体内壁）+ 淡淡地面投影。背景必须极简，因为跳一跳的核心是距离判断，复杂背景会干扰玩家。

2.3 蓄力与跳跃物理
// 蓄力阶段
chargeTime += dt;                                   // 上限 2.0 秒
power = Math.min(chargeTime / 2.0, 1.0);            // 归一化 0~1
distance = minDist + power * (maxDist - minDist);   // minDist 0.5, maxDist 6.0

// 起跳（松手瞬间计算完整抛物线，不做逐帧物理积分）
const flightTime = 0.55 + power * 0.35;             // 0.55~0.9 秒
const horizontalSpeed = distance / flightTime;
const verticalSpeed   = 0.5 * gravity * flightTime; // 保证落回同一高度
// 每帧插值位置，gravity 取 20~30（单位/秒²，游戏感优先，非真实 9.8）

必须预计算完整轨迹再插值，不要用逐帧重力积分（避免数值误差导致落点漂移）。
蓄力时显示：① 小人下蹲压扁；② 方块被压扁（scale.y 微降，模拟弹性）；③ 蓄力条 UI（底部横向进度条 + 数字力度值），这是可玩性的关键，必须有。
松手后：轨迹朝向为「当前方块 → 下一方块」的方向向量，玩家只控制力度不控制方向（与原游戏一致）。

2.4 落点判定与计分
const d = 落点到方块中心的水平距离;
const r = 方块半径（或半边长）;
if (d <= r * 0.18)      → 完美中心：combo++, score += Math.min(combo * 2, 32), 播放中心白点/涟漪特效
else if (d <= r * 0.95) → 普通落点：score += 1, combo = 0
else                    → 边缘/掉落：失败

完美落点反馈：方块顶部出现扩散白环（RingGeometry + opacity 衰减）+ 轻微弹跳（方块 scale.y 抖动 0.15 秒）+ 音效（若有音频模块）。连击数在 HUD 上以「×N」显示，连击越高字体越大、颜色越暖。
特殊方块停留彩蛋：落在特殊方块上后，停留 ≥ 2 秒不动触发：
  音乐盒（+30）：方块顶部小圆盘旋转，播放旋律（无音频时以旋转动画 + 音符粒子替代）
  便利店（+15）：卷帘门向上滑开，露出发光内部
  魔方（+10）：方块自身绕 Y 轴旋转 360° 完成「复原」动画
  井盖（+5）：方块轻微下沉 + 一圈水波纹
  触发后加分数飘字（DOM 或 Sprite）。每个特殊方块一生只触发一次，避免刷分。

2.5 关卡生成
初始生成 5 个方块，玩家每次成功跳跃后在前方补生成 1 个，并回收最远的 1 个（对象池）。
相邻方块间距随机 1.2 ~ 5.2 单位，方向在 ±35° 内随机偏转（不是纯直线，增加空间感）。
特殊方块出现概率约 15%，且不连续出现两个。
相机跟随：每次跳跃结束后，相机平滑（0.6~0.8 秒 easeOut）移动到「当前方块与下一方块连线中点」的后上方，保持等距斜 45° 俯视视角。相机移动必须在落地静止后才开始，避免跳跃过程中相机晃动干扰判断。

2.6 UI 与流程
进入 → 「开始游戏」+ 玩法说明（长按蓄力 / 落中心连击 / 特殊方块停留加分）。
HUD：左上角当前得分（大字号）、连击数、右上角历史最高。
失败 → 小人掉落动画（1 秒）+ 屏幕轻微变暗 → 结算浮层：得分、最高连击、踩中特殊方块数、历史最高、再来一次、返回大厅。
得分写入 localStorage（保留历史最高）。

2.7 验收标准
蓄力手感线性可预测，同一力度多次跳跃落点误差 < 2%。
完美中心判定半径合理（不能太苛刻，实测 10 次跳跃中普通人能命中 3~5 次中心）。
特殊方块 4 种彩蛋动画全部实现且只触发一次。
方块尺寸随分数递减生效。

模块 3+4：旋转木马重构（大厅外观对齐 + 游戏内第一人称坐姿视角）

3.1 问题
当前大厅里的旋转木马是「难看」的简化版，与游戏内设施不是同一个东西；游戏内是俯瞰视角，不是真实乘坐视角。

3.2 大厅外观重构（模块 3）
核心原则：大厅展示的旋转木马必须与 Carousel.js 内游玩时看到的是同一个模型，只是尺度不同。

实现方式（二选一，推荐 A）：
方案 A（推荐，零重复代码）：把旋转木马的建模逻辑抽成独立函数 buildCarouselMesh(scale)，返回一个 Group。大厅调用 buildCarouselMesh(0.35) 作为静态展示模型（不旋转或缓慢旋转 0.1 rad/s），Carousel.js 内部调用 buildCarouselMesh(1.0) 作为游玩模型。保证视觉完全一致。
方案 B：大厅直接实例化 Carousel.js 的模型部分但不启动玩法逻辑，需注意 dispose 时的资源归属（若共享 geometry/material，必须做引用计数，禁止一方 dispose 导致另一方崩溃）。

视觉细节要求（消除「AI 感」）：
中央立柱：CylinderGeometry，带螺旋条纹 CanvasTexture，metalness 0.85、roughness 0.25，金色。
顶棚：ConeGeometry（分段数 ≥ 24），红白/蓝白相间的扇形条纹贴图（CanvasTexture 手绘放射状色块），檐口加一圈小灯泡（SphereGeometry × 16，emissive 暖黄，夜间模式增强亮度）。
底盘：CylinderGeometry 扁圆柱，边缘加金色包边（TorusGeometry），台面贴大理石纹 CanvasTexture。
坐骑 ≥ 8 个：每个用 CylinderGeometry（躯干）+ BoxGeometry（腿/颈）+ ConeGeometry（耳/尾）拼搭抽象马匹，颜色必须各不相同（红/蓝/金/白/粉/绿/紫/橙），鬃毛与尾巴用薄片 BoxGeometry。每匹马身上有一根贯穿的金色立杆（CylinderGeometry，从底盘穿到顶棚）。
材质禁止全场景统一参数：金属件、油漆件、织物件必须分别设置不同的 roughness/metalness。

4.1 游戏内第一人称坐姿视角（模块 4）
彻底移除俯瞰视角，改为真实乘坐体验。

流程：
选马界面：进入设施后，相机以第三人称环绕旋转木马缓慢公转（OrbitControls 或程序化环绕），玩家点击任意一匹木马 → 该木马高亮（emissive 提升 + 外框描边或放大 1.05 倍）→ 底部弹出「骑乘这匹」确认按钮。支持左右箭头键切换选中项。
落座动画：确认后相机在 0.8 秒内平滑插值（Vector3.lerp + Quaternion.slerp）移动到该木马后上方的「骑手头部位置」，同时可选淡入一个极简的「双手扶杆」前景剪影（两个细 BoxGeometry 挂在相机下方，增强代入感；若影响视野则省略）。
乘坐视角：
   相机绑定到该木马的 pivot，位置为木马背部上方 (0, 1.15, 0.15)（相对于木马局部坐标），朝向木马前进方向。
   禁止 camera.add 进 Group，一律每帧 pivot.getWorldPosition(tmpVec) → camera.position.copy(tmpVec).add(localOffset)；pivot.getWorldQuaternion(tmpQuat) → camera.quaternion.copy(tmpQuat)。
   自由环视：在相机基础朝向之上叠加玩家的鼠标/触摸偏航与俯仰（yaw ±180°，pitch −40°~+50°），用 Euler 顺序 YXZ 合成。这是核心需求：可以四处看风景。
   木马的上下起伏（sin 驱动）必须传递给相机，产生真实的骑乘颠簸感，但幅度控制在 ±0.02 弧度旋转，避免眩晕（依据：屏幕晃动过快是致晕主因，需降低镜头速度）。
时长与退出：无倒计时限制（纯观赏），HUD 仅显示「下马」按钮 + 当前转速 + 「切换木马」按钮（点击后回到选马界面，转盘不停）。
防眩晕：FOV 设 70°（不要超过 90）；转盘转速 0.35~0.6 rad/s（依据：降低镜头移动速度可显著缓解眩晕）；提供「平稳模式」开关，开启后关闭起伏传递与所有晃动。

验收标准（模块 3+4）
大厅展示模型与游戏内模型肉眼可辨识为同一个东西（同建模函数、同贴图、同配色）。
游戏内视角确认为第一人称坐姿，可自由环视 360°。
选马交互流畅，高亮反馈明确。
连续乘坐 2 分钟无明显眩晕感（主观测试）。

模块 5：大厅椅子「坐下休息」

5.1 需求
大厅现有椅子/长椅是纯装饰，需增加交互：走近可坐下。

5.2 实现
为每张椅子注册可交互区域（Box3 或距离判定，半径 1.8 单位）。
玩家相机进入范围 → 屏幕中央下方浮现提示按钮「坐下休息 [E]」（键盘 E 或点击按钮）。
点击后：相机在 0.8 秒内平滑插值到「坐姿视点」——位于椅子座面上方 (0, 0.55, 0)，朝向椅子正前方（yaw 取椅子朝向），FOV 收窄至 60°（模拟放松状态）。
坐下后：
  禁用 WASD 移动，仅允许鼠标环视（yaw ±75°，pitch −25°~+35°，比行走时更受限，模拟颈部自然活动范围）。
  屏幕边缘轻微暗角（CSS radial-gradient 遮罩，opacity 0.25），营造放松氛围。
  可选：极缓慢的「呼吸感」相机微起伏，幅度 ≤ 0.01 单位、周期 4 秒（必须极微弱，超过则致晕）。
  HUD 显示「起身 [E]」。
起身：相机 0.6 秒插值回到站立视点，恢复移动控制，移除暗角。
状态互斥：坐下状态下禁止进入任何设施；进入设施前必须自动起身。

5.3 验收标准
走近/走远时提示按钮正确出现/消失，无闪烁。
坐下与起身过渡平滑，无跳变。
坐下时视角高度符合人体尺度（座面高约 0.45 单位 → 视点约 1.1~1.2 单位离地，需与项目整体尺度校准后确定）。

模块 6：迎宾 NPC 与动态人群

6.1 需求
大厅只有玩家一人显得空旷。用胶囊体生成约 10 个小人漫游，增加「人气」。

6.2 实现
建模（低成本 + 不假）：
每个 NPC = CapsuleGeometry(0.28, 0.9, 4, 8)（身体）+ SphereGeometry(0.22)（头），合并为一个 BufferGeometry 或用 InstancedMesh（10 个 NPC 颜色不同 → 用 InstancedMesh + setColorAt 实例色，一次 draw call 搞定）。
颜色：10 套不同的服装色（暖色系为主：砖红、藏蓝、姜黄、墨绿、灰紫、米白…），roughness 0.85、metalness 0。禁止用饱和度过高的荧光色（那是典型 AI 感来源）。
高度约 1.7 单位（与玩家相机高度一致），必须与大厅尺度校准——如果 NPC 比椅子矮一半或比门还高，真实感立刻崩塌。

行为状态机（4 态）：
WALK  → 沿路径点移动，速度 1.2~1.8 单位/秒，身体朝向移动方向（quaternion.slerp 平滑转向）
IDLE  → 停下，轻微左右摇摆（sin 驱动 rotation.y ±0.15 弧度），持续 2~5 秒
LOOK  → 「张望」：头部（或整体）转向最近的设施/其他 NPC，持续 1.5~3 秒
WAVE  → 迎宾专用：靠近入口的 1~2 个 NPC，玩家进入 3 单位范围时挥手（手臂摆动，若无手臂则整体轻微上下弹跳 + 头顶冒出「!」Sprite）

状态切换用加权随机 + 最短停留时间约束，避免频繁抖动。
路径：预先在大厅地面布置 8~14 个路径点（Vector3 数组），NPC 随机选点行走，到达后进入 IDLE/LOOK，再选下一个点（不选刚来过的点）。用 CatmullRomCurve3 可让路径更自然，但直线插值 + 转向平滑已足够。
避障：简化为「距离 < 1.0 时互相轻微侧向偏移」，不用做完整碰撞检测。
步行动画：无骨骼情况下，用 position.y += Math.abs(Math.sin(elapsed * 6)) * 0.05 做轻微上下起伏 + rotation.z 微幅左右摆动（±0.04 弧度），足以让静态胶囊「活」起来。

性能约束：
10 个 NPC 必须 ≤ 2 次 draw call（InstancedMesh 身体 + InstancedMesh 头，或合并为一个）。
每帧更新逻辑纯 CPU 计算，禁止每帧 new 对象。
视锥剔除：不在相机视野内的 NPC 跳过动画更新（仅更新位置）。

6.3 验收标准
NPC 行走自然，不穿墙、不穿设施、不重叠。
至少 2 个 NPC 具备迎宾行为（玩家靠近时有反应）。
draw call 增量 ≤ 2，帧率无可测下降。
NPC 与场景尺度协调（站在椅子旁、门旁时比例正确）。

模块 7：昼夜循环 + 烟花系统 + 烟花站台

7.1 时间控制台
大厅 HUD 增加「时间控制台」按钮（右上角，图标为时钟），点开面板：
  五个预设时段：黎明 / 正午 / 黄昏 / 夜晚 / 深夜（依据：检索结果  的程序化天空系统采用「黎明-正午-黄昏-深夜」四时段插值，此处按你的要求增加「深夜」独立档）。
  手动时间滑块：0~24 小时连续调节，实时预览。
  自动循环开关：开启后游戏内 1 分钟 = 现实 1 小时（可调倍率 0.5×/1×/2×）。
  面板可折叠，不遮挡视野。

7.2 太阳、月亮与光照
你提到「我的太阳之类的月亮，你也可以谋划一下」——以下是完整方案。

太阳/月亮视觉体：
用 PlaneGeometry + 自发光 ShaderMaterial（或 MeshBasicMaterial + CanvasTexture 径向渐变贴图）做圆形面片，始终 lookAt(camera)（Sprite 更简单，推荐 THREE.Sprite）。
太阳：暖白色 #FFF4D6 核心 + 橙黄光晕；月亮：冷白 #E8EEF7 + 淡青光晕，可选加月相（贴图 UV 偏移或明暗区遮罩）。
二者沿同一条弧线轨迹运行，相差 180°：太阳高度角 = sin((hour - 6) / 24 * 2π) * 最大仰角。

光照参数随太阳高度角变化（关键，依据  给出的实测色值表）：
太阳高度角   时段   天顶色   地平线色   平行光强度   环境光   备注
90°   正午   深蓝 #1E5BFF   灰白偏蓝   1.6   0.55   对比强烈，顶光锐利

45°   上午/下午   中等蓝 #3B78FF   偏白微暖   1.3   0.45   光照通透，阴影明显

15°   接近日落   蓝中带紫   橙黄渐变   0.9   0.35   暖色调开始出现

5°   黄昏   蓝灰   橙红大范围扩散   0.55   0.28   太阳周围呈火红色

−5°   入夜   深蓝至黑   暗红残留   0.15   0.18   夜光过渡区域

< −12°   深夜   近黑 #050814   深蓝   0.05（月光）   0.12   星空 + 霓虹主导

平行光颜色同步变化：正午 #FFFFFF → 黄昏 #FF9A4D → 夜晚 #6B8CFF（月光冷蓝）。
平行光方向必须与太阳位置一致（dirLight.position.copy(sunWorldPos)），否则影子方向穿帮，是最容易暴露「假」的地方。
天空实现：优先用 ShaderMaterial 球体（内壁 side: THREE.BackSide），片元着色器按视线方向 Y 分量在「天顶色 ↔ 地平线色」间插值，并叠加太阳方向的光晕项。参数通过 uniform 每帧更新（只更新 uniform，不重建材质）。
星空：夜晚（太阳高度角 < −6°）渐显 800~1500 颗 THREE.Points 星点，透明度随夜色加深线性提升，避免白天穿帮（依据：仅在太阳天顶角 > 96° 时激活星空渲染）。

7.3 夜间霓虹灯
为每个游乐设施（旋转木马、海盗船、跑酷入口、跳一跳入口、烟花站台）预置「夜间灯光组」：
  轮廓灯带：沿结构边缘布置的小球 InstancedMesh + emissive，或细长 BoxGeometry 自发光条。
  投光：每个设施 1~2 盏 SpotLight（全场景 SpotLight 总数 ≤ 6，PointLight ≤ 10，超出会严重拖垮帧率）+ 彩色 emissive 材质。
灯光强度随时间平滑过渡：nightFactor = clamp((−sunElevation − 2) / 10, 0, 1)，emissiveIntensity = base * nightFactor。禁止硬切换（一闪一闪很假）。
可选：霓虹灯做缓慢呼吸/流水效果（emissiveIntensity 用 sin 调制，频率 ≤ 0.5Hz，避免频闪致不适）。

7.4 自动烟花（夜间每 3~5 分钟一场）
粒子实现（性能关键）：
用 单个 THREE.Points + BufferGeometry 承载所有烟花粒子，预分配最大粒子数（如 3000），通过 drawRange 控制实际渲染数量。禁止每颗粒子一个 Mesh/Sprite（会导致 draw call 爆炸）。
粒子属性数组（Float32Array，init 时一次性分配）：position、velocity、life、color、size。
更新逻辑在 CPU 端（每帧遍历活跃粒子）或 GPU 端（自定义 ShaderMaterial + uniform time，更省 CPU，推荐）。
烟花生命周期：升空段（1 个亮尾粒子垂直上升 0.8~1.2 秒，带轻微拖尾）→ 爆炸段（瞬间生成 200~400 颗粒子，球形/环形/心形/柳形分布，初速度 8~14）→ 衰减段（重力 −9.8 作用 + 空气阻力 velocity *= 0.985 + 亮度随 life 衰减 + size 缩小）。
爆炸形状（至少 4 种）：球形（均匀球面随机）、环形（水平圆环）、柳形（初速小、重力大、寿命长，下垂如柳枝）、双层（内外两色）。
颜色：每次爆炸随机选一个主色系（金/红/蓝/绿/紫/银），部分粒子带二次变色（life 过半后 color lerp 到第二色）。
爆炸时可选触发一次极短暂的屏幕泛光（renderer 曝光微调，0.15 秒恢复）——幅度必须极小，避免闪烁不适。
光效：爆炸瞬间在该位置放一盏临时 PointLight（intensity 峰值 3，0.6 秒衰减到 0 后关闭），同一时刻最多 1 盏活跃，避免光源数量超标。

7.5 新设施：烟花站台 FireworksDeck.js
这是你要的「跟大家一起看烟花」的社交观赏点。

视觉构建：
一个抬高的圆形观景平台（CylinderGeometry，半径 6~8，高 0.6），边缘带低矮护栏（TorusGeometry + 立柱 CylinderGeometry × 16）。
平台中央一个「烟花控制台」（BoxGeometry 台面 + 倾斜面板 + 若干按钮状 CylinderGeometry，带自发光）。
平台周围摆放 4~6 张长椅（复用大厅椅子模型），朝向天空最佳观赏角度。
可选加分项：平台上放置 3~5 个 NPC（复用模块 6 的 InstancedMesh），进入 IDLE/LOOK 状态抬头看天，营造「大家一起看」的氛围。

玩法流程：
玩家走上平台 → 靠近控制台 → 提示「燃放烟花 [E]」。
打开控制台面板（DOM 浮层），包含：
   颜色选择：8 个色块按钮（金/红/蓝/绿/紫/银/粉/彩虹渐变）。
   型号/形状选择：球形 / 环形 / 柳形 / 双层 / 心形 / 随机。
   品类选择：单发（1 枚）/ 三连发（间隔 0.4 秒）/ 齐射（5 枚同时，扇形分布）/ 连珠（10 秒内每 0.8 秒一发）。
   尺寸：小 / 中 / 大（影响粒子数 150/300/500 与爆炸半径）。
   文字烟花输入框：输入 ≤ 8 个字符，可选字体大小（小/中/大）、颜色、是否闪烁。
   「燃放」按钮 + 「返回」按钮。
点击燃放 → 面板收起 → 相机自动切到「观赏机位」（平台边缘，仰角 35°~50° 朝向天空燃放点，0.8 秒平滑过渡）→ 烟花从平台前方 15~25 单位、高度 18~30 单位处升空爆炸。
燃放结束后 3 秒，相机归还玩家控制，控制台可再次使用（冷却 2 秒防止连点刷爆粒子池）。

文字烟花实现（技术要点）：
用离屏 Canvas 2D 绘制用户输入的文字（ctx.fillText，粗体、大字号），getImageData 取像素。
遍历像素，取 alpha > 128 的点，按固定步长（每 2~3 像素取 1 个）采样为目标位置数组。
烟花爆炸时，粒子不走向随机球形，而是从爆炸中心向各自的目标文字位置插值飞行（0.8~1.2 秒到位），到位后停留 2~3 秒（轻微抖动 + 闪烁），然后受重力下落消散。
文字粒子建议单独一个 THREE.Points 实例，避免与普通烟花粒子争抢池容量。
文字必须居中对称排布，与同时燃放的普通烟花形成「左右对称 + 中央文字」的构图（你要求的「跟烟花对称迎合」）：燃放文字烟花时自动在文字左右两侧各补 1~2 发普通烟花，时间错开 0.3 秒，形成呼应。
⚠️ 中文渲染依赖浏览器字体，CanvasTexture 需按模块 0.5 设置色彩空间；采样点数过多会拖垮帧率，文字粒子总数硬上限 1500。

7.6 验收标准
五档时段切换 + 连续滑块调节均无卡顿，光照/天空/阴影方向三者始终自洽。
夜间霓虹灯随日落平滑亮起，无硬切。
自动烟花在夜间按时触发，粒子池无泄漏（geometries 恒定）。
烟花站台四种形状、四种品类、八种颜色、文字
